## 上午：网络与基础体验

### 1. 公网部署调研与选择
- 对比了阿里云 99 元/年 2核2G 经济型 e 实例，确认够用（Node 服务端很轻）。期间把操作系统从默认镜像纠正为 **Ubuntu 22.04 64位**，购买后填公网 IP 即可跑一键部署脚本（脚本已就绪）。
- 在上云之前，先用 **cpolar 内网穿透**顶上：本地 8080 端口映射到公网 `https://67217a91.r22.cpolar.top`。之前测试报 404 其实是测试路径写错了，换成 `/api/` 前缀后 HTTP 请求完整穿透到本地服务器，互联网联机链路打通。
- 发现坑：**cpolar 免费版隧道 URL 在服务重启后可能变化**，客户端里写死的地址会失效。当天先做了"重启后一键体检脚本"兜底，长期靠上云根治（云服务器 IP 固定）。

### 2. 残局挑战内容重做
- 原来的残局设置不合理，重新设计了三个**符合开局合法性**的残局：
  - 单车擒王（红车+帅 vs 黑光杆将）
  - 马炮胜双士（红马炮+帅 vs 黑将+双士）
  - 双车错（红双车+帅 vs 黑将+双士）
- 三局都满足将帅不对脸、开局无将军、红方必胜。

### 3. 货币 + 糖果 + 人机开局设置
- 人机对战货币结算：**赢 2000￥ / 输 500￥ / 平 1000￥**。
- 商城三种糖果是消耗品：笨糖果 10 秒 / 一般糖果 15 秒 / 聪明糖果 20 秒 AI 思考时长；单机、互联网对战、局域网房客可用，房主和观战不可用；糖果按钮旁实时显示剩余数量。
- 单机开局前弹设置窗选 **AI 难度 + 执子方**，开局后锁定不可改。
- 性能顺手优化：博弈树置换表从 1<<22 调到 **1<<21**，冷启动工作集只有 3.5MB。

### 4. 好友列表空状态
- 空列表不再是冰冷的"暂无好友"，改为大号小奶龙 + 引导文案占位，占位项不可选中、双击不误触邀请，加了第一个好友自动恢复。

## 下午：表情包与头像（全链路）

### 5. 奶龙表情包 11 张全链路
- 11 张表情（s01~s11）打包进 `stickers.qrc`，客户端内置渲染，聊天只传文本标记 `[sticker:sNN]`，正则校验后双方本地画图——**不传图**，天然兼容局域网 UTF-8 透传和互联网 WebSocket。
- 对局聊天和好友私信共用同一个 StickerPicker 选择器与渲染逻辑。
- 踩坑：QSS 写了 `hover:{}` 应为 `QPushButton:hover{}`；还有一次全角逗号当参数分隔符直接编译错误——**C++ 里中文标点是隐形炸弹**。

### 6. 真实双客户端 E2E 测试
- 用 UIA 自动化双开客户端实测：互联网私信、局域网对局聊天两条链路，s01~s11 全部发送/接收/渲染正常。
- 测试基建沉淀：PrintWindow 截图不受重叠和 DPI 影响；UIA 填表单要跳过只读 QTextEdit；QWidgetAction 内嵌按钮不进 UIA 树只能物理坐标点（本机 125% DPI，物理坐标=虚拟×1.25）。
- 测试中抓到一个真 bug：**私信按钮只读 currentItem()，UIA 程序化选择列表行时不触发 current 行变化**，误报"请先选择好友"。参照邀请按钮补了 `selectedItems().first()` 兜底。
- 测试脚本和截图留档在 e2e 目录，测试账号保留，后续回归直接复用。

### 7. 好友列表显示头像
- 根因是服务端 `/api/friends` 没返回头像字段：服务端补 `avatar_url`，客户端 FriendInfo 加字段。
- 头像异步下载后**圆形裁剪 36×36**；无头像用户自动生成"按 id 取色的彩色圆底 + 名字首字"默认头像；用 URL 缓存防重复下载。
- 下载完成的信号要带 URL 参数区分是哪个用户的头像，否则多个下载并发会画串。
- 踩坑：PowerShell `Invoke-RestMethod -Form` 上传头像的 mimetype 是 octet-stream 会被 multer 拒，换 `curl.exe -F "avatar=@file;type=image/png"` 解决。

## 晚上：体验补全与服务自动化

### 8. 「返回主菜单」按钮与关窗不退出
- 现象：单机对局没有回主界面的按钮，点 X 直接整个程序退出。
- 根因：所有开局路径里 StartScreen 都会 `close()` 自己，所以关掉对局窗=程序里最后一个窗口没了。
- 修复：对局窗按钮行最左加「返回主菜单」按钮（所有模式含观战可见），并在 `MainWindow::closeEvent` 末尾 **new 一个新的 StartScreen 拉起来**（自动登录态保留）；联机未结束时先弹确认防误触断线。好友面板同款加了「返回」。

### 9. 装饰性礼物

- 收礼端富文本弹窗展示大 emoji + 送礼人 + "第 N 份礼物"累计计数。
- 走既有 gift 事件；离线好友诚实提示无法收礼（不再假成功）。

### 10. 开始界面背景音乐（当天最后一战）
- 需求：把用户提供的 mp4 转成音频在开始界面循环播放，音量适中，可以关。
- 实现：ffmpeg 转 22050Hz 16bit PCM 单声道 wav（3分18秒，8.3MB）→ qrc 嵌入 exe；StartScreen **懒加载 QMediaPlayer**（性能铁律：播放器构造会同步初始化 Media Foundation，放构造函数里"开始游戏"会卡 4 秒）→ `setLoops(Infinite)` 循环、音量 0.4；showEvent 后 400ms 起播、hideEvent 立即停（防新旧菜单双音乐）；左下角「🎵 音乐」按钮开关，QSettings 持久化。
- "疑似静音"排查记录（几轮弯路，值得记）：
  - 先怀疑 qrc 没嵌进去——**qrc 文件名表是 UTF-16 编码，ASCII 搜索搜不到 ≠ 没嵌入**；
  - 自动化音频峰值探测脚本不可靠（拿它测系统自带音效也报静音，自证失败）；
  - 最后用窗口标题诊断法：诊断代码把 QMediaPlayer 状态写进窗口标题，UIA 读标题验证。发现播放中 **MediaStatus 停在 BufferedMedia(5) 是常态**，真正判断"在不在播"要看 PlaybackState；第一版诊断代码拿 `PlayingState`（属于 PlaybackState 枚举）跟 MediaStatus 比较，编译警告 -Wenum-compare 且恒 false；
  - UIA 实测 `ps=1` 确认一直在播，之前的"静音"是误报；
  - 功能验证：开关切换 → ps 0↔1 + 注册表 startMusicOn 同步变化；进对局停、返回主菜单自动续播全部通过。
- 验证窗口状态时又踩一个 UIA 坑：**owned QDialog 打开时，父窗口元素的 Name 会把对话框标题拼接进来**，造成"对话框残留"假象——最后用 Win32 EnumWindows 列真实 HWND（class/title/vis）一锤定音。

### 11. 服务器开机自启 + 一键体检
- 计划任务 CandyboardServer：登录 Windows 时经 wscript 无窗口启动 node 服务端（先检测 8080 未监听才启动，日志落 server\autostart.log）。
- 体检脚本 `tools\check_cpolar_url.ps1`：一键检查 cpolar 服务 / 8080 监听 / 隧道当前 URL 是否与客户端默认地址一致，不一致红字给出处理步骤。踩坑：cpolar debug 日志刷屏极快，NewTunnel 记录可能在最近 2000 行之外，**查当前 URL 要全文件 Select-String 取最后一条**。
- 端到端验证：公网地址请求 `/api/friends` 返回 401（合法未登录响应），穿透正常。

## 当天沉淀的通用经验

1. **性能铁律**：耗时初始化不能放构造函数，挪到 singleShot(0) 也不行（只是把卡顿挪到窗口显示后堵死事件循环），必须真懒加载或后台线程。
2. **qrc 缓存**：替换资源后构建无效时，删影子构建目录里的 `qrc_*.o` 重新编译；查资源是否嵌入要用 UTF-16 编码搜索 exe。
3. **UIA 自动化 Qt 程序**：QDialog/QMenu 是 owned window 挂在 owner 的 UIA 子树（不在 root 子级）；窗口真伪用 EnumWindows 验，别信 UIA Name 拼接。
4. **PowerShell 工程**：内联 here-string 传 C# 必挂，Add-Type 脚本必须写 .ps1 文件用 -File 跑；schtasks 传带引号参数是引号地狱，直接用 Register-ScheduledTask。
5. **免费内网穿透的不可靠性**：URL 会漂移、依赖本机开机——免费方案适合开发期，正式交付必须上云（固定 IP + 24 小时在线）。
6. **中文标点进 C++**：全角逗号/括号编译报错信息往往很隐蔽，报错先查标点。

## 十、成就/商城/背包改简约风 + 置换表懒分配省 64MB

**1. 配色统一简化**——用户反馈成就殿堂、商城、背包三页太鲜艳。全部改为白底卡片+灰边框+深灰文字+深灰按钮的简约风：去掉橙渐变货币卡、紫/粉/绿/红彩色卡片与按钮、mimimimi 紫渐变改白底灰虚线，强调只靠字重不再靠色。emoji 图标保留（是内容不是装饰）。加上之前回退的主菜单，全应用配色已统一为朴素风。

**2. 置换表懒分配**——原来 `static TTEntry* TT = new TTEntry[TT_SIZE]()` 在进程启动时分配 200 万槽位（64MB）并整表清零，不管用户玩不玩 AI 都白占内存、拖慢启动。改为 `ttTable()` 首次进入搜索才分配清零：主菜单/联机对局全程省 64MB，实测主菜单进程私有内存 47MB（之前应为 ~110MB）。TT 条目本来就有 key 校验，懒分配不影响正确性。

**3. 启动实测**——主菜单窗口 1.2 秒出现（UIA 轮询就绪 3.2s 是测试工具开销，非应用耗时）。启动路径已无大块同步初始化：QMediaPlayer 懒加载、QSoundEffect singleShot(0) 绑定、置换表懒分配。
